### #1065 · Meta: no insights row is not a campaign giving up its code

- **Branch:** `cc/` · head `2aa797e`, 14 Oct · 1 commit · 177 behind main.
- **Files:** 5, in `lib/insights/` and `lib/dashboard/rollup-sync-runner.ts`. No migration; doesn't touch CLAUDE.md.
- **What it does:** the rollup's campaign union (`fetchEventDailyMetaMetricsUnion`, Pass 2) drops a stored campaign id whenever the insights edge has no rows for it in the 60-day window. In practice that means "this campaign didn't spend lately", not "this campaign is no longer ours". The PR keeps an id unless its name shows another event's `[CODE]`. It also adds a Pass 0 that lists campaign objects by `[CODE]` from the campaigns edge, so the list rebuilds itself even when a campaign hasn't delivered.
- **On main?** No. `lib/insights/daily-meta-union.ts:146` still reads `if (!res.ok || res.campaignIds.length === 0) continue;`. Main hasn't touched these files since the PR's base.
- **Still biting (prod, read-only):** `events.meta_campaign_id` today is shorter than the PR's dry run expected:

  | Event | Stored ids now | PR's 60-day count |
  |---|---|---|
  | NX26-MF | 4 | 7 |
  | NX26-IPC | 4 | 7 |
  | NX26-RUDIMENTAL | 2 | 3 |

  NX26-IPC was at 5 when the PR was written (6 → 5), so its list has shrunk again since. HE1's attribution reads this column through `metaCampaignOwners`. The `[CODE]` fallback covers most of it, but not a campaign whose name lacks the code.
- **Conflicts:** none.
- **Recommendation: merge.** It isn't visual, so it needs no design record. Re-run CI on a fresh merge first (it is 177 commits behind), then run the PR's dry run once more.
