Diagnosis: branch `cursor/meta-afs-website-destination` (off main 4a9159b, read-only, no PR). ## How the reads were made

GET only, Graph version `META_API_VERSION` from `.env.local`, token resolved like `resolveServerMetaToken` (`user_facebook_tokens.provider_token` first; it was used). Fields requested on each creative: `object_story_spec, asset_feed_spec, call_to_action_type, object_type, link_url, link_destination_display_url, degrees_of_freedom_spec, platform_customizations`. Meta accepted every field. `call_to_action_type`, `link_url`, `link_destination_display_url` and `platform_customizations` came back **absent on all three creatives** (unset), so they are not the difference.

Plus one scan: `GET act_606252931141334/ads?fields=creative{asset_feed_spec{…}}`, every page, keeping creatives with `asset_customization_rules` (723 ads).

## Fields that differ, A (app) vs B / C (Ads Manager)

Structural — present in B and C, absent in A:

1. `asset_customization_rules[i].link_url_label` on **every** rule, pointing at a label on `link_urls[0].adlabels`.
2. `link_urls[0].adlabels`: one label per rule (2 in B, 3 in C).
3. `link_urls[0].display_url: ""`.
4. `asset_customization_rules[i].body_label` / `title_label` on every rule, and matching `bodies[0].adlabels` / `titles[0].adlabels`.

Content the operator chose (not structure):

5. `call_to_action_types`: A `BUY_TICKETS`; B `BOOK_TRAVEL`; C `LEARN_MORE`.
6. `link_urls[0].website_url`: B drops the tracking query string; C keeps it.
7. `titles[0].text`: A `" "`; B and C `""`.
8. `ad_formats`: A and B `SINGLE_IMAGE`; C `AUTOMATIC_FORMAT` (mixed media).
9. `degrees_of_freedom_spec`: B and C list fewer features, and opt in to some (B: video_auto_crop, video_filtering, video_uncrop, product_browsing; C: standard_enhancements). Enhancements — not to be copied.
10. C only: `message_extensions: [{type: whatsapp}]`.

Identical in all three: `object_type: SHARE`, `object_story_spec` = `{page_id, instagram_user_id}` only, `optimization_type: PLACEMENT`, `additional_data`.

## What the reads can and can't show

The leading candidate is 1–3: Ads Manager ties each placement rule to a link URL, and the app doesn't. That matches the single-mode case, where the link sits on the CTA. But the reads can't separate it from 5 (CTA), because neither reference uses BUY_TICKETS. Nor does any read say what Ads Manager *displays* as Main destination. The account already contains the ads that separate the two causes:

| Open in Ads Manager | Shape | If it shows Website… | If it shows Facebook event… |
|---|---|---|---|
| 120251882396650755 | BUY_TICKETS **with** link_url_label | labels fix it; CTA isn't the cause | labels aren't enough |
| 120252067913800755 | SIGN_UP, **no** link_url_label | CTA (BUY_TICKETS) is the cause | missing labels are the cause |
| 120251749404850755 | hand-built, LEARN_MORE | confirms C as the Website reference | — |

## Step 2 as first proposed (superseded by the fix below)

If the first ad shows Website and the second shows Facebook event: in `buildMultiPlacementCreative` (and in `buildVariationRotationCreative` only if it has rules — it has none today, so its shape question is separate), give `link_urls[0]` one adlabel per rule plus `display_url: ""`, and add `link_url_label` to each rule. ## Fix: Book now as BOOK_TRAVEL in asset_feed_spec

### Dry run before any POST

`validate_only` exists (`execution_options=["validate_only"]`). Results, saved in `scratch/afs/validate-only-*.json` (not committed). The payloads are the exact output of the new `buildCreativePayload` (dual mode, image and video, real hashes / video ids from act_606252931141334, page 156873374377231, IG 17841401779330825):

| Call | CTA in `asset_feed_spec` | Image | Video |
|---|---|---|---|
| `POST act_606252931141334/adcreatives` | BOOK_TRAVEL | `success: true` | `success: true` |
| same | BOOK_NOW (control) | `success: true` | `success: true` |
| `POST act_606252931141334/ads`, inline creative, `status PAUSED`, ad set 120252046313540755 (OUTCOME_SALES, INITIATED_CHECKOUT, the ad set of 120252046313680755) | BOOK_TRAVEL | `success: true` | `success: true` |
| same | BOOK_NOW (control) | 400, code 100, subcode **1885396** "The call-to-action type BOOK_NOW is not supported for the objective OUTCOME_SALES in dynamic creative ad set." | same 1885396 |

Creative-level validate_only does not check the CTA (the BOOK_NOW control passes), so it proves nothing on its own. The check runs when the ad is placed in an ad set with an objective, which is also why PR #574 saw it per objective. At that level BOOK_TRAVEL passes and BOOK_NOW fails, for image and video. A read afterwards found 0 `zz validate_only` ads in the ad set (3 ads, unchanged) and 0 `zz validate_only` creatives in the account: nothing was created.
