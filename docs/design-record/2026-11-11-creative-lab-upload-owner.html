The event page's upload folder, owner first

A follow-up to 2026-11-11-creative-lab-drive-owner-type.html. Its D3 retires Content from new cycles, but the upload panel (lib/drive/panel.ts stageFolder, the 9 Nov record's S23 and CLS7) still preselects 03 Creatives / 3 On sale / w/c {d Mon} / Content for any file it can't place elsewhere. From w/c 23 Nov that folder won't exist. This record rules what the panel offers instead. S23's other preselections (00, 01, Artist clips, Press kits) stand.

Rulings

#Ruling
U1 On sale: owner and type, chosen in the rowThis takes option (b). The creatives row reads 03 Creatives / 3 On sale / w/c {d Mon} / {owner} / {type}, and the last two parts are pickers inside the row.
  • Owner:
    • The list is the Lab lineup in billing order, each name exactly as D1 writes it, then the promoter: the client's name, or {Client} (promoter) on a clash.
    • It's preselected only when the file name names exactly one lineup artist, using S23's existing match (the longest name wins).
    • Otherwise it reads choose who it's for, and Upload waits for it. The owner is never guessed: a wrong guess puts the file in another team's approval folder, the one Matas shares with them.
  • Type: taken from the file's MIME when it's certain: video/* → Videos, image/* → Statics. Anything else reads choose Videos or Statics, and Upload waits.
  • Never the stage or cycle folder itself: option (a) is not offered. D4 leaves those folders holding only owner folders, so a file at cycle level would be the one thing an approval share can't see.
  • The current cycle only, as S23 had it. An older cycle is reached through Another folder in the tree… and gets the same two pickers.
U2 The other stagesThe same row and pickers, for whichever stage is current:
  • signup → 03 Creatives / 1 Signup / Teaser / {owner} / {type}, replacing S23's bare 1 Signup;
  • show week → 03 Creatives / 4 Show week / {owner} / {type}.
Announcement, Presale live and Reminders stay under Another folder in the tree…. Choosing one shows the same two pickers. A stage folder chosen there never takes the file directly.
U3 A finished creative isn't source footageS23 sends "a video named for an artist" to 02 Source / Artist clips / {artist}, which imports it into the Lab as a clip. A finished edit carries the artist's name too, so the two need telling apart.
  • A file whose name follows S14's render pattern is a creative. That means it starts with the event's code and has _9x16, _4x5 or _1x1 before the extension or _winner, for example P26-BDAY_luke-dean_artist-card-3_on-sale_9x16_v1.png.
  • Such a file is preselected to the creatives row, with the owner from the name and the type from MIME.
  • Every other file follows S23 as before.
U4 Words and states
  • Preselected with both known: the row is selected and its small line reads likely — "{artist}" in the name, S23's own form. The promoter is never preselected. A promoter file is chosen by hand, because a file name can't say it belongs to no artist.
  • Owner unknown: the picker reads choose who it's for, Upload is dimmed, and the line under the row reads Choose who it's for — the file goes in their folder for approval.
  • Type unknown: the picker reads choose Videos or Statics, and Upload is dimmed.
  • Folder not made yet (D5): Makes {owner} / {type} in {w/c d Mon} with this upload., using the stage's own name for Teaser or 4 Show week. It's said once, under the row. No folder is made until Upload.
  • An artist renamed in the Lab: the picker shows the Lab's current name. The upload goes by the owner's key, so it lands in that artist's folder even while D5's rename of the Drive folder is still on its way. No extra words.
  • An artist removed from the lineup: they're not in the picker. Their old folders stay (D5) and are reached through Another folder in the tree….
  • Safety net: a key that resolves to no folder and can't be made (for example the retired Content of a new cycle) refuses with the panel's existing That folder isn't in this event's tree — choose another. Content is never made again.
U5 Elsewhere on the event page
  • Only the upload panel's words change.
  • The Drive panel's now: 3 On sale / w/c {d Mon} line is unchanged: it names the stage, not a folder to drop into.
  • The render rows' "in Drive" mark is unchanged.
  • The asset board's + needs … lines point at 01 and 02 and are unchanged.
  • The usual-folders list in the panel loses the … / Content row and gains the creatives row of U1 or U2.
U6 The deadline
  • This ships no later than the first Monday on which a cycle is made under D3. For P26-BDAY that's Mon 23 Nov, when w/c 23 Nov is made with no children. The target is a deploy by Fri 20 Nov.
  • If it slips, U4's safety net stands in: an on-sale upload preselected to the retired Content is refused with the existing sentence, never filed into a newly made Content.
  • cc/drive-owner-type must keep that refusal: with CYCLE_CHILDREN empty, specFor no longer resolves …/content, and the upload must refuse rather than make the folder.
