The live ads' page, at launch review

This is check 8b, from Ops and Matas, ruled word for word:

  • For a published draft, compare its stored page and Instagram with the live ads' identity.
  • Read them once, at launch review, and never on every render.
  • When they differ, show a warning, not a blocker: "This draft runs from {draft page}; the live ads run from {live page}. Relaunching uses the draft's."

The case is NX26-DOD's On sale draft:

  • The draft runs from Ironworks London and @puzzleofficialuk.
  • The live ads run from NX LOVES and @dj_dod.

What this amends: RC3's list of checks, with one warning, and page_other_client's fix and evidence when the live identity is known.

What stands: everything else in #1359, its word list included. The read is built in CC-2 (#1361).

Ruling

#Ruling
RC8 · identity_not_live (warning)
  • When it runs.
    • Only for a published draft: one with live ads.
    • At launch review, the app reads the live ads' Facebook page and Instagram account once, and compares each with the draft's.
    • Nothing reads Meta while the draft is being edited.
    • A draft that has never launched has no live ads, so the check doesn't run.
  • Page and Instagram are separate lines, as with page_other_client, because each has its own answer:
    • page: "This draft runs from {draft page}; the live ads run from {live page}. Relaunching uses the draft's.";
    • Instagram: "This draft runs on Instagram as @{draft handle}; the live ads run as @{live handle}. Relaunching uses the draft's.";
    • the key word is "Live ads";
    • evidence: "Read from the live ads at {date, time}: {n} ads", or "1 ad".
  • Two fixes:
    • first, "Use the live ads' page: {live page}" (or "…Instagram: @{handle}"), which sets the draft to it in one click;
    • second, "Keep {draft page}" (or "Keep @{handle}").
  • Keep works as "Keep this link" does:
    • it clears the warning for that draft until the draft's page or account changes;
    • it stores who kept it and when;
    • it shows as one muted line under the list, "Page kept by {name}, {date, time}: {draft page}".
  • It never blocks. Launch stays on.
  • Names keep their case. A page name or handle inside a fix button keeps its case even though the button's own words are set in capitals: "USE THE LIVE ADS' INSTAGRAM: @dj_dod". This applies to every fix that carries a name, #1359's included.
  • When the live ads are mixed (some on one page, some on another), the check names the page most live ads use, and the evidence counts those ads. When the read fails, the check is silent rather than guessing: no line, no warning.
RC8a · Next to page_other_client
  • One field, one line. When page_other_client fires on a field (the draft's page or Instagram is another client's), identity_not_live doesn't show a line for that same field. The blocker carries the answer instead:
    • its first fix is "Use the live ads' page: {live page}" (or "Use the live ads' Instagram: @{live handle}");
    • its evidence adds "· the live ads run from {live page}" (or "· the live ads run as @{live handle}");
    • "Change the page" stays as the second fix.
    So Matas sees one problem with one answer (Ops' recommendation, ruled as is).
  • The live answer is only offered when it's safe. If the live ads' own page is another client's, it isn't offered, and the blocker reads as #1359 has it.
  • Fields are judged separately. On a draft where only the Instagram is another client's, the page can still show identity_not_live while the Instagram shows the blocker.
  • Order. identity_not_live sits with the warnings, after the blockers and before link_not_event.

Acceptance

  • NX26-DOD: two blockers, each with "Use the live ads' …" first, and no identity_not_live line. One click sets NX LOVES and @dj_dod, after which the draft launches clean.
  • Another Electric page on the draft: the warning shows for each field that differs, and Launch is on. "Keep" clears it and writes the kept line, and changing the page brings it back.
  • A draft never launched: no read, no warning.
  • The read: one Meta read per launch review, none while editing (CC-2's test). A failed read shows nothing.
  • Live page another client's: no "Use the live ads' …" fix is offered.

  • The majority rule for mixed live ads, and silence when the read fails.

  • The ad count and the read time.
