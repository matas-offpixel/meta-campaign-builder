Overlay templates — issue 7: kit fonts, provided means cleared

Matas, 10 Nov: "When a font is provided that's it — we are working from promoter open files, an extension of their marketing. Up to them to have the right licences." This issue re-rules the kit font. It supersedes O24's server-render hold (issue 3, as applied in issues 4–6) and withdraws O45 (issue 6). Everything else in issues 1–6 stands. The question that remains is delivery, not licence: where the font file lives and how a render gets it.

Rulings

#Ruling
O49 Provided is clearedA kit font that arrives with the client's open files or brand kit (a PSD's linked fonts, a brand-kit folder, a file the client or their designer sends) is cleared for every render: local, Lambda and the CI runner, stills and video. There is no licence record, no proof upload and no use to tick. The licence is the client's to hold: Off/Pixel works from their files as an extension of their marketing.
O50 O45 withdrawnIssue 6's O45 is withdrawn in full. That means no "Licence · Add proof" line on the Brand kit's font row, no _Brand kit / Licences folder, no "Licence recorded · server · video · {who}, {d Mon}", and no "Held — {face}: licence for server rendering not recorded". H43 is withdrawn with it. If any of it was built, it comes out.
O51 O24 otherwise standsKit type renders only in the kit's own faces. No stand-in face, no fallback stack and no system font, ever. A face enters a kit only from the client's own files: the kit stores which file or folder each face came from and when (kept for the record, never on screen, rule 5). A font Off/Pixel bought or found is never added to a client's kit. J2 stays held for PP Neue Machina until that file arrives from the client.
O52 Delivery, not licence
  • Never in git. No kit font file (.otf, .ttf, .woff, .woff2) is committed: not in fixtures, not in evidence, not in public/.
  • Never in the public Remotion bundle. The Lambda site's serve URL can be read by anyone, so no kit font goes into the site bundle, its public/ folder or any static asset it serves.
  • Private storage. Each face is stored in the kit's own private storage bucket, under the client's kit. It is never in a public bucket. offpixel-event-assets is public-read, so fonts never go there.
  • Loaded at render time from a signed URL made for that one render and expiring within an hour. This is the same path on Lambda and on the CI runner. The signed URL is never written to a log, a database row, a frame artifact or the render's stored props beyond the render itself.
  • No face, no render. If the face doesn't load, or the loaded face's name isn't the kit's PostScript name, the render stops before the first frame. Nothing falls back (O51). The card reads "Held — {face} didn't load for this render · retry".
  • The CI runner reads the bucket with a read-only credential scoped to kit fonts and kept as a CI secret. No font file goes into an uploaded artifact or a cache.
O53 The knock-ons
  • #1163's follow-up. T2 cards a, b and c at 9:16, 4:5 and 1:1 become CI frames now: T2-a-916, T2-a-45, T2-a-11, and the same for b and c. These are nine frames at output size. The hyphenated ids are new; T2a and T2b stay the schematics of issues 4 and 5. The frames render with the draft stamp off, because they are fixtures, never filed or exported. Once they land, docs/evidence/t2-claim-statics-round-3/ is no longer the evidence. It stays in the repo as history and is no longer cited.
  • T1 on a clip (issue 6, H36–H46) may render on Lambda. Nothing in H36–H46 waits on a licence any more. H44's preview check still applies before the first clip ships.
  • Issue 6's question 9 (the kit-font licence) is closed by O49–O50.
