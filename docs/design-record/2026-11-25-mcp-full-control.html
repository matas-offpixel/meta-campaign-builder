Off/Pixel · design record · MCP · full control · 25 November 2026 · re-rules 2026-11-25-mcp-today-actions (TD1–TD4) for Meta changes

A yes in Claude runs it; Today keeps the log

Matas ruled on 25 Nov: for Meta changes through the connector, his typed yes in Claude is enough. The spec is scratch/mcp/m3-full-control-2026-11-25.md. This record re-rules the TD record for those changes. The merged record isn’t edited.

  • Each mcp:meta call carries the question Claude asked and Matas’s answer, word for word.
  • Today stops being the gate. Its Claude section becomes the log of what ran, with Undo where one exists.
  • The client ceilings are the money backstop, and Matas sets them in Settings › Claude.

What stands:

  • TD’s row layout, colours, ids and counts-only results.
  • Step 0’s actions and change lines.
  • TD4’s connector page, except its Meta line.
  • Approve and Reject on Today, which now serve only M4’s render packages (record #1379). A render isn’t a Meta change.

Rulings

#Ruling
FC1 · Today, a log
  • The section is titled “Claude’s changes”, with “{n} today” beside it. TD3’s ceiling lines stay under the title, and a client with none reads “{client}: no daily ceiling, so Claude can’t start spend”.
  • Each call is one row, newest first, today only; older calls stay in the action log. A row has:
    • the title “{action} · {code}” and Step 0’s change line;
    • “Approved in Claude · {date, time}”, with “What Claude asked”, which opens the question and Matas’s answer, word for word, in quotes;
    • the outcome: TD’s “Done · {result}” with the created, added, launched or changed form and its one-form, or “Failed · …”.
  • Refused calls are logged too, muted, with their short reason: no approval, ceiling, no ceiling, checks, switch, test cap. That puts a call with no approval in front of Matas.
  • Undo, where one exists, with a line saying what it does:
    • on a pause: “Undo resumes it.”, and the reverse;
    • on a budget change: “Undo puts it back to £{x} a day.”;
    • on a budget move: “Undo moves £{x} a day back to {from}.”;
    • on paused objects Claude made: “Undo deletes the {n} paused {things} Claude made.” This one confirms once, because a delete can’t be undone.
  • Undo is Matas’s own action. Afterwards the row reads “Undone by {name} · {date, time}”. An Undo that starts spend (resuming) meets the same ceiling, and reads “Undo refused · {reason}” if it would pass it.
  • No Undo:
    • when the object changed after Claude’s change: “Changed since, so Undo is off.”;
    • on a live launch: “It’s live, so Undo can’t delete it. Pause it in the campaign tree.”
FC2 · Refusals told to Claude
  • Plain text that Claude relays and Matas reads, each ending “Nothing was sent to Meta.”:
    • no approval;
    • over the ceiling;
    • no ceiling, for a change that starts spend;
    • launch checks ({n}, with a one-form);
    • switched off;
    • a test over £10.00 a day.
  • The no-approval line tells Claude what to do next: ask Matas, then send his exact question and answer.
  • The no-ceiling line says where a ceiling is set.
  • When a change runs, Claude is told “Done: {result}.”, then “Matas can undo this on Today.” wherever an Undo exists.
FC3 · Daily ceilings
  • A section in Settings › Claude: one row per active client, A–Z. Each row has:
    • the client;
    • “£{c} a day · £{s} a day running now”, or “No ceiling” (muted);
    • “Changed {date} by {name}”.
  • Only Matas (MATAS_USER_IDS) sees the buttons: Set, or Change, which opens the row with “£ a day”, Save, Cancel and “Remove ceiling”. Remove confirms once.
  • Everyone else sees the list, with “Only Matas sets ceilings.”
  • Until this screen ships, scripts/set-client-ceiling.mts sets them.
FC4 · Files sent at Launch
  • The launch progress has no step for uploads today. Two steps go first, in the existing form:
    • “Sending {n} files to Meta…”;
    • then, when any are videos, “Waiting for Meta to finish {n} videos…”.
    After that, the existing steps run from “Validating configuration…” on.
  • Review & launch: where the pending-file blocker was, it reads “{n} files go to Meta when you launch.” A pending file with no stored copy still blocks.
  • If an upload fails: the launch stops before anything is created: “Launch stopped: {n} files didn’t reach Meta, so nothing was created.” The slot shows the existing “Upload failed — retry or remove”.

Acceptance

  • Every connector change is a log row with the question and answer exactly as stored. A refused call is a muted row.
  • Undo:
    • it restores the before state through the same path (a test checks each pair);
    • an Undo that starts spend meets the ceiling;
    • it’s off once the object has changed;
    • a delete confirms once and removes only paused objects Claude made.
  • Ceilings: only Matas can set them (a test checks it), and every change records who made it and when.
  • Launch: pending files with a stored copy send first, then the launch runs. A failed upload creates nothing.
  • Words: every string is a row, exactly. No raw Meta error reaches the screen or Claude.

Invented here

  • Every word.
  • Rules:
    • refused calls shown on the log;
    • Undo off once the object changed;
    • no Undo for a live launch;
    • Undo held to the ceiling.
  • Frame contents: ids, times, money, the asked and answer text, and the ceilings.
