Off/Pixel · design record · MCP · Claude’s requests on Today, and the connector page · 25 November 2026 · before M3

Claude asks; Matas approves on Today

M3 is request-then-confirm. Claude asks for a Meta change through the connector. The change happens only after Matas approves it on Today, in Off/Pixel, and never on the strength of the Claude chat alone. This record gives the words and frames for:

  • the request list on Today;
  • Approve and Reject, and what Claude is told back;
  • each client’s daily ceiling (client_spend_ceilings) and the refusal when a request would pass it;
  • the connector page in Settings.

Words appear only where Matas sees them. Tool names, scopes and ids stay in the log, never on screen. M3’s Meta line on the consent page is M3’s own record, not this one.

Rulings

#Ruling
TD1 · Claude’s requests on Today
  • A section titled “Claude’s requests”, first on Today while anything waits, with “{n} waiting for you” beside the title. When nothing waits, it reads “Nothing waiting from Claude.” and moves below the day’s brief.
  • Each request is one row:
    • the action and the show’s code, “Change budget · NX27-GLITTERBOX”, with the action in plain words, never the tool’s name;
    • what changes: “[NX27-GLITTERBOX] ON SALE: £40.00 → £55.00 a day”;
    • who and when: “Requested by Claude for Matas · Wed 25 Nov, 10:14”.
  • Five states, each one line in its colour:
    • Requested (ochre edge): Approve and Reject;
    • Approved (ink): “Approved by Matas · …”, while Meta runs it;
    • Done (olive): “Done · 1 ad set changed · 120251748789350755”;
    • Failed (brick): “Failed · 2 of 3 ad sets changed · …”. Counts and ids only, never Meta’s message;
    • Rejected (muted): “Rejected by Matas · …”, with the note in quotes when there is one.
  • Two outcomes Matas never had to act on show muted, in the same list:
    • Expired: a request not approved within 24 hours is dropped, and nothing is sent;
    • Refused (brick): a request that would pass the client’s ceiling (TD3) never waits for approval.
  • Requests run oldest first while waiting. Finished ones run newest first under them, for today only. Older ones stay in the action log.
TD2 · Approve and Reject
  • Approve runs the change at once, with no second confirm: the row already says exactly what changes.
  • Reject opens one optional field, “Why (Claude sees this)”, and its own Reject button.
  • What Claude is told (the tool’s answer, which Matas reads in Claude):
    • on request: “Waiting for Matas to approve this on Today.”;
    • then the outcome: done, failed (with its counts), rejected (with the note), expired, or refused.
    Claude never hears that something is done before Meta has answered.
  • Only an approval on Today counts. A “yes” typed in Claude changes nothing.
TD3 · Each client’s daily ceiling
  • Under the section title, one line per client with waiting or recent requests: “Electric: £96.00 of £150.00 a day”. That’s planned daily spend against the ceiling.
  • A request that would pass the ceiling is refused before it reaches Matas. Its row reads “Refused · it would take Electric to £162.00 a day, over its £150.00 ceiling”, and Claude is told the same, with “Nothing was sent to Meta.”
  • A client with no ceiling reads “Puzzle: no daily ceiling, so Claude’s Meta requests are refused”. With no ceiling set, nothing is allowed, rather than everything.
  • Only Matas sets a ceiling (MATAS_USER_IDS). Where it’s set is its own surface, not drawn here.
TD4 · The connector page
  • Settings gains a “Claude” section, for operators.
  • Not connected: it gives the address to add in Claude, with Copy. The connection is always made from Claude, never from this page.
  • Connected:
    • “Connected since {date} · last used {date, time}”;
    • three scope rows (Read, Drafts, Meta), each Allowed or Not allowed. Meta reads “Not built yet” until M3.
  • After an upgrade (#1372’s fix): one muted line, “Drafts allowed since {date}; the read-only connection it replaced is closed.”
  • Disconnect asks once: “Disconnect Claude? It stops at once. Nothing it made is undone.” It revokes every grant for the user. The page then reads “Disconnected {date, time}.” over the not-connected state.

Acceptance

  • A request reaches Meta only after Approve on Today. A test shows Claude’s request alone writes nothing.
  • Every state shows its words exactly, with counts and ids only.
  • Claude is told “Waiting…”, then the outcome, never “done” before Meta answers.
  • A request over the ceiling, or for a client with none, is refused before it’s listed as waiting, and nothing is sent.
  • Disconnect revokes every grant for the user. After an upgrade, the old read grant is already revoked (#1372).

Invented here

  • The 24-hour expiry.
  • No ceiling meaning no Meta changes.
  • The order of rows.
  • Every word.
  • The figures, ids and times in the frames.
