From Drive: bulk-prepare ads from the event's folders

Matas, 12 Nov: "an integration between our Google Drive and campaign launchers for quicker upload to campaigns. Drive folders appear there, multiple select of content (perhaps keeping the multi select to 9:16 files only to avoid placement issues), the ad upload should detect if static or video, select for which page, and bulk uploads in one go."

Where it lives: the Meta launcher's creatives step, components/steps/creatives.tsx. That component is the same in the wizard, the canvas drawer (▤ creatives) and /campaign/[id], so the picker ships in all three.

What the step does today:

  • Its drop zone Drag & drop files to bulk-create ads or browse creates one empty ad per dropped file. Each copies the active ad's identity, captions, headline, URL and CTA (handleBulkUpload).
  • Bulk Upload inside an ad adds variations.
  • Apply to all copies headline, description, URL and CTA across the draft.

This record adds a third source next to drag and browse, reads the event's Drive tree, and fills the ads it makes.

Rulings

#Ruling
G1 The entry and the tree
  • Entry: a From Drive button in the drop zone, after browse. It opens a picker (DL1): a dialog 960 px wide at 1280, full-screen at 393.
  • It opens the campaign's event's own tree (the event's map in drive_folders), at the current stage's owners. That stage is the on-sale cycle w/c {d Mon}, 1 Signup / Teaser or 4 Show week, as stageFolder picks it.
  • Owners come from the tree map, not from position. P26-BDAY's owner folders were mapped in place under the hand-made w/c 9 Nov / Content. They still show as the stage's owners, and the breadcrumb shows the folders' path by stage and owner, not the Drive path.
  • Order: the lineup in billing order, then the promoter (U1's order). Any other child folders follow under Other folders here.
  • Below the owner, the folders are read as they are in Drive. Today that's Videos / UGC · CTA · No CTA and Statics / CTA · No CTA, as made in the Off / Pixel Shared Drive on 12 Nov. No record rules that layer yet (the owner-type record stops at Videos / Statics). The picker shows those folders by name and doesn't depend on them.
  • The breadcrumb: every segment opens its folder. The cycle segment is a menu of the event's cycles, newest first, so older cycles are one choice away. 03 Creatives opens the other stages.
  • Empty states:
    • no event on the campaign: Link this campaign to an event to pick from its Drive folder.
    • an event with no tree: This event has no Drive folder yet — make it from the event page's Drive panel., with Open event ↗
    • Drive can't be read: Off / Pixel can't read this event's folder — check the export account can see it.
    • an empty folder: Nothing in {folder} yet.
    Each one keeps browse working.
G2 Selection and 9:16Files show as tiles:
  • Drive's own thumbnail, fetched through the app, since Drive's link needs the account;
  • the ratio badge, the duration for video, the file name (cut in the middle) and its size;
  • {n} of {m} selected · Select all 9:16 ({k}) · None, within the open folder.
The ratio comes from videoMediaMetadata / imageMediaMetadata (width, height, rotation), with 2 % tolerance (the crop's own). A file Drive hasn't measured yet is selectable and reads Size checked when copied. If it turns out not to be 9:16, that ad fails with the reason below.

Disabled, never selectable, with a reason:

  • a video that isn't 9:16: Not 9:16 — video runs as 9:16 only (O95, O104). The proposal's "runs in Feed only" isn't true of video, so it isn't used;
  • a static that isn't 9:16, in Single: Not 9:16 — pairs with its 9:16 in Dual or Full;
  • a file over the step's own limits (MAX_VIDEO_BYTES 200 MB, MAX_IMAGE_BYTES 30 MB): Over 200 MB — too large to upload here (or 30 MB).

Dual and Full apply to statics only. A video always makes a Single 9:16 ad whatever the batch's mode, and its row says Video runs as 9:16 only.

For statics in Dual or Full, the 9:16 is the tile. Its 4:5 (and its 1:1 in Full) are found in the same folder by the S14 name with only the ratio token different, and shown on the tile as + 4:5, + 1:1. Those siblings aren't separate tiles. A 9:16 missing its sibling is disabled: Needs its 4:5 or Needs its 4:5 and 1:1. A file without an S14 name can't be paired, so it runs only in Single.

G3 KindImage or video from the file's MIME (video/*, image/*). It sets the ad's Media Type and its asset slots. A mixed selection makes mixed ads, one per file. The existing "all files must be the same type" rule stays on Bulk Upload inside one ad, where it belongs.
G4 The batch's fieldsA bar at the top of the picker, filled once and written into every ad it makes. Each ad stays editable afterwards. The fields and their defaults:
  • Primary text: empty on the first batch.
  • Headline: empty on the first batch.
  • URL: the event's ticket_url; with none, the draft's last ad's URL; else empty.
  • CTA: the draft's last ad's CTA; with no ads, the objective's default.
  • Page and Instagram: the draft's last identity, through the step's existing resolution (the page's linked Instagram, never overwriting an operator's pick).
The owner folder doesn't switch the identity by itself. W3 writes artist-footage captions in the promoter's voice, so the client's Page is the safe default. When Matas picks an artist's account (for example @enzosiragusa), that pick is remembered for that owner for the rest of the session (G7).

At 393 the bar collapses to one line of values with Edit.

G5 PreparePrepare {n} ads makes one ad per selected file (one per set in Dual or Full), added to the end of the draft. Nothing launches: Launch stays its own, separate step.
  • Name: the file name without its extension when it's an S14 name. Otherwise {owner's first name} - {folder} {n}, matching Enzo - UGC 3.
    • {folder} is UGC, CTA or No CTA, or Video / Static when the file sits straight in Videos or Statics.
    • {n} continues from the highest number already in the draft for that owner and folder.
    • When two owners share a first name, the full name is used.
  • No duplicate: a file whose drive_file_id is already an ad in this draft is skipped with Already in this draft — skipped.
  • The source: each ad's asset slot shows From Drive · {folder path}. The sidebar row adds From Drive to its sub-line.
G6 The copy (what the operator sees)Each file goes Drive → Storage (streamed, #1188 / #1189's path, deduped by creative_assets on drive_file_id, migration 228) → Meta (video by META_VIDEO_UPLOAD_MODE=file_url's signed link, images as today). Each row moves through these states:
  • Copying from Drive… {pct} %
  • Sending to Meta…
  • Ready
  • when the registry already holds the file: Already in Off / Pixel — sending to Meta…
  • on a failure:
    • Couldn't copy from Drive — Retry
    • Meta didn't take this file — {reason}, the reason through the step's existing plain-words error
    • Not 9:16 — video runs as 9:16 only, from G2's check on copy
One failure never stops the batch.
  • The head line reads Preparing {n} ads · {k} ready.
  • The end line reads {n} ads prepared · {s} skipped (already in this draft) · {f} failed — Retry.
  • Retry failed ({f}) reruns only the failed files.
  • Closing the dialog doesn't stop the copy. The ads finish in the draft, with their own slot states.
G7 The next ownerAfter a batch, the picker stays on the same folder and shows Next: chips for the same path under each other owner (Luke Dean / Videos / UGC, Puzzle / Videos / UGC), so the next batch is one click away. An owner without that folder shows — empty and is disabled.
  • The batch's fields are kept, with a Clear fields text button.
  • The identity follows G4's per-owner memory.
  • Done closes the picker.
G8 TikTokNot in this record. TikTok's ▶ video tab will mount the same picker; its fields (identity, the caption field, its own spec) and its words need their own ruling. Build the picker as a shared component that takes the step's fields and identity from the host.
