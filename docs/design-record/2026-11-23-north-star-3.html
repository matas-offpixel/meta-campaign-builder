0 · The loop — Signal → Memory → Decide → Act → Learn

One loop runs across CIRQLIN, Off/Pixel and every ad channel. Each layer has one question:

  • Signal: what happened?
  • Memory: what do we keep, and with what evidence?
  • Decide: what should change?
  • Act: who or what makes the change, and through which gate?
  • Learn: did the change work?

The two products split the loop as the map says. CIRQLIN feeds Signal (pages, signups, consent, community, ticket clicks) and Act (Phases, sends). Off/Pixel runs Memory, Decide and Act across Meta, TikTok and Google. Claude operates Act through the MCP, from a phone. Learn feeds Memory, which closes the loop. Today it's the missing return path: actions don't become evidence.

item states: live partly designed / record queued missing · from the map's "Where we stand", 23 Nov

Where each product sits. CIRQLIN is Signal and Act for fans: it owns the page, the consent, the phase and the send. Off/Pixel is Memory, Decide and Act for ads: it owns the learnings, the proposals and the launches. Neither owns Learn alone. A phase change (CIRQLIN) is the boundary every ad learning is cut at (phase curves, E2b). A purchase traced back to a CIRQLIN signup is what Off/Pixel's buyer-quality score needs.

Claude's place. Claude operates Act, through the MCP, and is never the only route to a learning (OP8). Every Learn and Decide item above runs on the platform's own crons and key. Claude only makes them faster to act on.

2B · Phases is the moment engine

CIRQLIN Phases (cirqlin #666, PH1–PH13) makes each stage of a page a saved phase that switches by hand or on a timer. Issue 3 makes that switch the one clock for the show. A phase switch, a scheduled update (such as the lineup drop) or a return from Final tickets emits one moment: page, show code, phase, time, and who or what fired it. Off/Pixel subscribes.

Rules for the engine:

  • One clock. For a show with a CIRQLIN page, the page's phase plan is the source of the moments. Off/Pixel's event_key_moments and milestones mirror it read-only. A show with no page keeps Off/Pixel's own moments. There are never two clocks for one show.
  • Approve the moment, not each subscriber. The spending subscribers (push, pauses) are approved when the moment is scheduled, as one card listing every write. Changing the moment's time keeps the approval. Changing what it writes asks again.
  • Each subscriber is idempotent on the moment's id, has its own kill switch and runs in shadow first (OP: "kill switch on every write path, default off; shadow before live").
  • A failed subscriber never blocks the others. It shows on Today as a red row naming what didn't happen. The ticket-link guard (PH9 a) blocks only the switch itself.
  • Consent first (OP11). The D2C subscriber sends only to signups whose consent snapshot covers the channel. CIRQLIN audiences reach ads only under the new wording (§8, C4).

6 · Keeping it current (issue 2's rules, then issue 3's)

  • Same PR, same card. A PR that changes an area's state also changes that card's state in this map, by issuing the next map record with the card moved and a changelog line, in the same PR or its paired docs PR. The reviewer checks the card moved.
  • Card before build. A new area gets its card (state Not designed or Designed) before any build PR for it. No card, no build.
  • Every capability has a row. (Issue 2.) Anything that runs, a cron, a table with a writer, a flag-gated path, is a row on a card with its state. A capability with no row is this record's failure: add the row, then move the card. Removing a row needs a changelog line saying why.
  • A chain link is a gap until it carries rows. (Issue 2.) The learning chain in §1B is checked on every re-issue against live counts. A link marked missing or partly stays in §5 until rows flow and something reads them.
  • Expert items have a home before they're built. (Issue 2.) A deck rule goes into the deck record; a learning job names its store and reader on the Learning loop card; a watch names its platform fact and date. None is built from a chat message.
  • Re-issue, never edit. The map is re-issued as docs/design-record/YYYY-MM-DD-north-star-{n}.html. The new issue copies the last one, extends the changelog at the top, and changes only what moved. Old issues stay as they were.
  • States mean exactly this. Live = on main, used on real data, with rows. Partly built = on main with a named part missing, empty, flag-off or stale. Designed = a record exists. Not designed = no record yet.
  • Markers are rules, not decoration. A ✋ on a card means no code path may act there without Matas's yes. Adding or removing one is a design ruling, so it needs a record.
  • Review checklist addition. Every design review states the card(s) and row(s) it touched and their state after the PR.
  • Every row names its layer. (Issue 3.) A capability row or a gap row without one of Signal, Memory, Decide, Act or Learn (or Ops, for the five operator cards outside the loop) is incomplete. A row that sits in two layers names both, primary first.
  • A finding type ships with a negative test. (Issue 3.) Every new kind of finding comes with at least one case it must not report, from real data. The date pairs of 16–22 Nov are the first. Without one, the type stays in shadow (OP3).
  • A link on the return path is a gap until a decision has its outcome. (Issue 3.) RP6–RP8 count as live only when a logged decision has been scored at 7 days and the score reached a rule.
  • Claude-only paths are interim and labelled. (Issue 3.) Anything that only works through Claude (the morning brief task, the interim inspiration task, the Meta connector) writes into the app's own store and carries an "interim" label wherever it shows, until the platform's own writer replaces it (OP8).
  • Operator work becomes an action, not a screen. (Issue 3.) A new operator-only screen needs a record showing why an MCP action can't do the job (OP9, as ruled in §2A).
  • Gaps carry an exit test. (Issue 3.) A §5 row without a checkable exit test can't be built against. The test uses real figures where the data exists (the map's acceptance rule).
