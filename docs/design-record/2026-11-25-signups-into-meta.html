A show’s signups, on Meta, and where Matas sees them

This records SU as built in #1367 (merged; migration 267 applied). The spec is scratch/campaign-replicate/signups-to-meta.md, with CLAUDE.md under OFFPIXEL_META_CUSTOMER_LIST_WRITES_ENABLED. It supersedes the SU brief sent earlier.

  • Each show gets one list, “{code} · Signups”, in the event’s ad account.
  • The list is made on presale day at 08:00 London (general-sale day when there’s no presale). It’s kept current every morning to show day from CIRQLIN’s hashed read, and rebuilt in full every Monday at 08:00, so an erasure leaves it within 7 days.
  • Nothing is written to genre lists. Instead, the show’s list joins each of its client’s templates that include the show, as a customer list with role signups.
  • A show is switched on one at a time, by script. Today NX27-GLITTERBOX and NX27-SILVABUMPA are on. The switch is OFFPIXEL_META_CUSTOMER_LIST_WRITES_ENABLED, exactly “true”.
  • Hashes are never stored, and rows and logs carry counts only, so every line here is a count.

What stands: everything else in RT15 and RC5. RB and RD from the retargeting record take SU1’s line where they draw the Signups line.

Rulings

#Ruling
SU1 · The Signups line in Bottom
  • It sits where RT15’s line sits, under Bottom’s sources. It takes the place of RT15’s line once the list exists, and is set like the Buyers line beside it (“Buyers from Skiddle · 412 sent · updated …”).
  • One state at a time, in this order of precedence:
    StateLine
    Not switched onRT15 as it is: “No signup list yet, so Bottom runs on {sources} only.”, with its link.
    Switched on, before presale day“No signup list yet: it’s made on Fri 27 Nov, 08:00, so until then Bottom runs on {sources} only.”
    On Meta“Signups list · 412 signups · last sent Wed 25 Nov, 08:00 · rebuilt in full Mon 23 Nov”
    CIRQLIN has no page with the tag (brick)“CIRQLIN has no page tagged {tag}, so this show’s signups can’t be sent.” The tag is printed exactly as stored.
    CIRQLIN’s read isn’t set up (brick)“The CIRQLIN read isn’t set up, so no signups are sent.”
  • Added under the line, when they apply:
    • writes off (ochre): “Sending signups to Meta is switched off, so this list isn’t kept current.”, or before the list exists, “…so the list won’t be made until it’s on.”;
    • a failed CIRQLIN read (brick): “The last run couldn’t read CIRQLIN, so nothing new was sent. The next run tries again tomorrow at 08:00.”;
    • a send Meta didn’t fully take (brick): “Meta took 380 of 412 signups in the last run. The next run sends the rest tomorrow at 08:00.”
  • Never a raw error: no Meta or CIRQLIN message, code or id. The log keeps those, in counts.
  • “Signups” counts what’s on the list now: everything sent, less the removals (withdrawn consent, deletions). “Rebuilt in full” is the last Monday replace, or the day it was made, before the first Monday.
  • One form for every count: “1 signup”, and “Meta didn’t take the 1 signup in the last run…”.
SU2 · In the template tab
  • Each show’s list is an item under Customer lists, after the genre lists, titled with the list’s own name, “NX27-GLITTERBOX · Signups”.
  • Its line is “Customer list · role: signups · NX27-GLITTERBOX · 412 signups”. When the list sits in another account, templates.item.held follows it.
  • Before the list is made, the line has no count: “Customer list · role: signups · NX27-SILVABUMPA”.
  • Its status is Reused once the list exists. Before that it reads “Made on Fri 27 Nov” in the dashed style, never “Will be created”: the sync makes it, not the template, and Create never touches it.
SU3 · On the event page
  • One line under the Linked campaigns tree, once the list exists: “Signups in Meta: 412 in NX27-GLITTERBOX · Signups, last sent Wed 25 Nov, 08:00.”
  • No line before the list exists. A problem shows in the retargeting panel (SU1), not here.
SU4 · Dates and counts
  • Dates use the campaign creator’s forms: “Fri 27 Nov”, and “Wed 25 Nov, 08:00” for a moment, in London time.
  • Counts use thousands separators: “1,204 signups”.

Also ruled here: video-viewer items in the template tab (#1363 follow-up, CC-3)

A template’s video-viewer item (“50% watched · 30 days”) stores only a threshold and days. Meta needs video ids. Reading every video on the page isn’t safe: a promoter’s page holds other shows’ videos. So the ids come from this show, picked by Matas.

#Ruling
RC-E · the item
  • Before any videos are picked:
    • the status is “Needs videos” in ochre, dashed like “Will be created”;
    • under the item’s own line, in ochre: “Meta needs this show’s videos, so Create leaves this out until they’re picked.”;
    • under that, the button “Pick this show’s videos”. The label is the same on every video-viewer item, and each item has its own button, because each carries its own threshold and days.
  • The button opens the Audiences step’s video picker as it is, on this show’s videos, with the item’s threshold and days set. Its header line is “From {template}: {threshold} watched · {days} days. Pick this show’s videos.” Nothing is ticked for Matas.
  • After the picker saves:
    • the line under the item reads “{n} videos picked from {code}” (or “1 video picked from {code}”);
    • the status goes back to “Will be created”, and Create counts the item;
    • the button becomes “Change videos”.
    The picked videos belong to this draft only. Save to template never stores them: the template keeps threshold and days.
RC-E · the footer
  • It names the count left out, so the footer adds up to the rows above it: “9 reused · 1 will be created in NX Promoter · 1 needs videos picked.” For more than one: “{k} need videos picked”. The part is dropped when there are none.
  • “Create {m} audiences…” and “{m} will be created” never count these items.
  • When writes are off and only one is waiting: “Creating audiences is switched off, so this one waits.” This is a new one-form for templates.writes_off.
  • When everything left is a video-viewer item (m = 0):
    • the Create button is hidden;
    • the footer reads “{n} reused · {k} need videos picked.”

Acceptance

  • NX27-GLITTERBOX (switched on, presale Fri 27 Nov):
    • before that day, Bottom reads the waiting line;
    • after the 08:00 run, it reads the list line with the count the run sent.
  • A show not switched on reads RT15’s line, byte for byte.
  • Switch unset: the ochre line shows under whichever state applies, and no request leaves for Meta.
  • not_linked and not_configured show their brick lines, and nothing is written.
  • A failed run shows counts only, with no Meta or CIRQLIN text on screen (a test checks it).
  • Template tab: NX27-GLITTERBOX · Signups is an item in every Electric template whose shows include Glitterbox, and Create never counts it.
  • Words: every string is a row, exactly.

Invented here

  • Every line in SU1–SU3.
  • “Rebuilt in full”.
  • “Made on {date}” as a status.
  • The counts, times and the tag “NX27 Glitterbox” in the frames.
