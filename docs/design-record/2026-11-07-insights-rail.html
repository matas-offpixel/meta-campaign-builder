The Insights rail — what's working, beside whatever you're building

Matas: "I'm not seeing the overall insights — captions, creatives, variations, styles. Have it to the right of the event info tabs, like a side panel I can expand / retract at all times. Useful not only on this page but across the board." This record draws one rail for every operator page. It reads the page it sits on, opens on the insights that matter there, and gives at most one action per insight. Frames are at 1280 and 393 in Off Pixel's tokens. The rules are docs/creative-lab/design-rules.md, especially 6 (units and a comparison), 8 (empty states say what unlocks them) and 12 (cross-client data is Matas-only), plus the insight chip / bars and verdict chip components.

Every figure in the frames is real unless it's marked placeholder. They come from tag_performance as it stood on 7 Nov (90-day window) for Puzzle (vertical music) and for all clients. Lab verdicts, copy lines and lookalike or retargeting results don't exist yet, so those sections are drawn as the honest empty states they'll be at launch.

R · Rulings

#Ruling
R1 PlacementA right-hand rail on every page under the operator layout (app/(dashboard)). At ≥1200 px it pushes the page (the content column narrows by 360 px); it never overlays. Between 768 and 1199 it opens as a drawer over the content, below the page header, so the header's own buttons stay reachable. At 393 it's a bottom sheet.
R2 Rest stateCollapsed by default: a 34 px tab down the right edge reading Insights with a ‹ (IR1). Tap the tab or ‹ to open and › to close. The state is remembered per user in the browser (localStorage, key op.insightsRail), so no migration. It's one state for every page: open stays open as you move between pages.
R3 Never on client pagesThe rail is mounted by the operator layout only. It's never on /admin/[clientSlug], /share/* or /l/*, and no client-facing component imports it (rule 12). CI checks this by DOM (IR0).
R4 ContextEach page declares {surface, clientId?, eventId?, stage?, objective?}, and the rail reads it. Stage defaults from the page: an event that's on sale → Ticket sale, announced or registration → Signup, the campaign drawer → its objective's stage. A page with no client (Today, Calendar) opens on All clients.
R5 ScopeThis client · Vertical · All clients (the insight chip's scope toggle). Default is This client. When a section has no strong or ok row at that scope, that section alone falls back to the next scope, with one ochre line saying why (IR2). It never silently mixes scopes. Vertical and All carry a 🔒 line: "🔒 Across clients · Matas only". Today the whole rail is Matas-only; the lock line keeps this explicit for when the team grows.
R6 BarsOne bar per option, length = cost per result, with a dashed tick at the scope's own baseline. Each bar is labelled £3.85 / signup · 8% under, where the % is against that scope's baseline. Colour reads shrunk_index: olive ≤ 0.95 (ok or strong only), brick ≥ 1.10, otherwise ink. Thin rows draw no bar and read "Not enough data yet: n funded ads" in muted text. They never show a confident bar or a %. Four bars at most, then "+n more".
R7 Result lineEvery section opens on one result sentence above its bars. If the best ok/strong option beats the runner-up by ≥ 0.05 index and is olive, it reads "{Option} costs {n}% less than usual." Otherwise it reads "No clear winner between {A} and {B}.", drawn as a result, not an error. All thin reads "Not enough data yet."
R8 Confidence lineUnder every section, in mono: {strong|ok} · {funded ads} funded ads · 90 days · {scope}. When the rows differ it uses the weakest shown.
R9 One action, where it helpsOn the event page an angle maps to the Lab generator: artist_headliner → Lineup, urgency_scarcity_fomo → Scarcity, visual format pov → POV. When the section's winner maps, it gets Use {angle}, which scrolls to Captions and pre-selects that angle without generating. Scarcity still needs the ticket data that makes it true (rule 11); the generator enforces that, not the rail. In the audience builder each cluster gets Add cluster. Everything else is read-only.
R10 NamesNo raw keys (rule 5). A label map ships with the rail, for example lifestyle_image_with_text → "Lifestyle image with text", urgency_scarcity_fomo → "Urgency / scarcity", event_announcement_update → "Event announcement", cinematic_b_roll → "Cinematic B-roll". An unmapped key shows Title Case and logs a warning.
R11 393Collapsed, the rail is an Insights pill in the page header row, never floating, so it can't cover a sticky primary action (IR7). Open, it's a bottom sheet at 86% height with a scrim, closed by swipe-down or ✕. The sheet uses the same section layout as the rail.

IR1 · Event page, rail collapsed (1280)

The tab is the whole rest state: no badge, no count, nothing that pulls the eye off the page. It sits beside the page, not on it, so it can't cover the Approve button or any other primary action.

IR2 · Event page, rail open — ticket-sale stage, Puzzle has no sale results (1280 and 393)

Puzzle is on sale, so the rail opens on Ticket sale. Puzzle has no attributed sales, so each section falls back to All clients, says so in one ochre line, and shows the 🔒 line. Use Scarcity appears because the winning angle maps to the Lab generator. It pre-selects Scarcity. The generator still refuses scarcity copy without the ticket count that makes it true (rule 11).

IR4 · Campaign creation — MML canvas / Meta drawer, Signup, Leads objective (1280 and 393)

In campaign creation, copy leads: Best lines, then Proven elsewhere, then the creative sections. Stage and objective come from the drawer. Once lines exist, Best lines shows up to 3 example lines with their £ / result and the "vs event" index, and each Proven chip gets one action, Use line, which drops it into the focused copy field. Both are empty today and say exactly what fills them.

IR5 · Audience builder — interest clusters with live results (1280 and 393)

Clusters rank by cprIndex, which is against each client's own baseline, so the £ figures across clients aren't compared directly. The % comes from the index (1 − cprIndex), not from a shared baseline. That's why Music festivals (£0.98) sits below Disc Genre (£1.06). Clusters default to Vertical, because clusters carry their own vertical and per-client results are mostly thin. Add cluster adds it to the audience being built.

IR6 · Event page with Lab verdicts (fixture, as CL6) — the action and the Lab section filled (1280)

Expected figures are from the CL6 fixture, as in scripts/plan-frames/README.md: Lineup £0.50 / signup × 40 = £20, POV £0.75 × 20 = £15, (0.75 − 0.50) ÷ 0.75 = 33%, round total £35 / 60 = £0.58. Use Lineup pre-selects Lineup in the generator. The Lab section always leads the event-page rail once a round is judged. It's the client's own, freshest evidence.

IR7 · 393 rest state — the trigger lives in the header (393)

No floating button at 393. The Insights pill sits in the header row, so it can't cover a sticky Approve or Create button. Tapping it opens the IR2-393 sheet.
