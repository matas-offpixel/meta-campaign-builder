How to read it

  • The map (§1) reads left to right, then down: a brief arrives → event and lineup → landing page and D2C → audiences → campaign in MML with the Insights rail → Creative Lab and the asset bank → launch → reporting and the learning loop, which feeds back into the rail. Operator pages that serve every stage sit underneath.
  • Each card has a state: Live Partly built Designed, not built Not designed. A ✋ You approve marker means nothing moves until Matas says yes. A ⚙ Runs itself marker means the tool acts on its own and reports what it did on Today.
  • §2–§4 redraw the three pages Matas lives in: Today, the event page and the client page. §5 lists the gaps and ranks the top five by the hours they'd give back. §6 is how this map stays true.
  • To check a PR: find its card. The PR moves the card's state, or it shouldn't touch that area.

1 · The map

LivePartly builtDesigned, not builtNot designed✋ You approve⚙ Runs itself◆ = where the Insights rail sits

Where Matas approves, and nowhere else: the brief read-back (1), artist rights (2), every D2C send (3), each launch (5, 7), every caption (6) and every ticket warning (6). These are the five gates the job sits on: rights, captions, launches, ticket warnings and D2C sends.

Where the tool acts on its own, and reports on Today: CQ list sync (3), clip discovery (6), round proposals (7, proposal only), weekly judging (8), the nightly sweep, tag and copy scoring (8), and later the ticket sync (2). It never launches, pauses or sends by itself.

Where the insights sit (◆): the Insights rail on the event page, the audience builder, the MML canvas and drawers, and inside the Lab. The client page carries its own learnings section (§4), which reads the same data at client scope.

2 · Today — the operator's start page

Three blocks, in this order: Needs you (anything waiting on Matas, one action per row), Done overnight (what the tool did, read-only), Next 7 days (calendar, payday outlined when it falls inside). The current Today's sections fold in: Alerts become rows in Needs you (critical) or Done overnight (info); Pending action, Happening today and Needs attention become rows in Needs you.

Rules on Today: a row exists only when it can be acted on, and its button is the action (rule 4). A row leaves when it's done; a dismissed info signal goes to Done overnight. Every number carries its comparison (rule 6): "CPA £53.59 vs £6.57 median", "1,912 of 2,000 sold". Health alerts (tokens, AWS/Lambda render failures, API errors, failed crons) land in Needs you at the top. Today is where the ⚙ marks on the map report.

3 · The event page, whole

Header: title, client · state · payday · days to go; View client and Edit. Tabs stay as they are (Overview, Plan, Campaigns, Reporting, Activity), and Active Creatives folds into Campaigns. The Overview tab runs top to bottom: Facts → Lineup → Creative Lab → Asset bank → D2C comms → Campaigns → Reporting. Lineup moves out of the Lab, because the landing page, D2C and SEO read it too. The Insights rail sits beside the page (its own record).

4 · The client page — what Matas sees, and what the client sees

The client page today has ten tabs. The north star keeps them but opens on an Overview that answers five questions in order: what's on (events by stage), how it's going (rollups against the client's own band), what we've learned for this client, what's connected, and which artists are cleared. The client's own portal is a separate, smaller page: their events, their sales and spend, their reports. It never shows other clients, the rail, cross-client learnings, internal notes or fees beyond their own invoices (rule 12).

6 · Keeping it current

  • Same PR, same card. A PR that changes an area's state also changes that card's state in this map. It does that by issuing the next map record with the card moved and a changelog line, in the same PR or its paired docs PR. The reviewer checks the card moved.
  • Card before build. A new area gets its card (state Not designed or Designed) before any build PR for it. No card, no build.
  • Re-issue, never edit. The map is a record: it's re-issued as docs/design-record/YYYY-MM-DD-north-star.html. The new issue copies the last one, extends the changelog at the top, and changes only what moved. Old issues stay as they were.
  • States mean exactly this. Live = on main and used on real data. Partly built = on main, with a named part missing. Designed = a record exists. Not designed = no record yet. A switched-off feature is Partly built.
  • Markers are rules, not decoration. A ✋ on a card means no code path may act there without Matas's yes. Adding or removing one is a design ruling, so it needs a record.
  • Review checklist addition. Every design review states the card(s) it touched and their state after the PR.
