It adds 36 rows to the word list and keeps all 151 existing rows word for word. One ruling differs from Ops' recommendation: RC11, the event picker.

What stands: everything else in #1359 and #1362. Frames RC-B and RC-F from #1359 are replaced by RC-B2 and RC-F2 below.

Rulings

#Ruling
RC9 · One ad set, one campaign
  • Every tree string with a count has a one form, picked by n, as the launch checks do (RC3):
    • addition rows: "+ 1 ad added", "to 1 ad set", "→ 1 ad set";
    • the sheet's title: "Add 1 creative to {stage}";
    • a campaign's count: "{n} of 1 ad set";
    • the button: "Add to {n} ad sets in 1 campaign", and "Add to 1 ad set in 1 campaign".
  • With nothing ticked, the button is off and reads "Nothing ticked".
  • Replicate's kept line gets the same: "Objective, 1 ad set, budgets, …".
RC10 · A campaign with no draft on the event
  • A campaign the event links to but no published draft on this event made (one built in Ads Manager, say) stays in the tree, under its stage, with its status and ad sets, so the whole stage still shows.
  • It reads muted, with one line under its name: "No draft on this event, so additions can’t reach it."
  • In a sheet it's listed, unticked, and can't be ticked, with the same line.
  • Ops suggested "Built in Ads Manager, …". That isn't always true: a draft deleted, or made for another event, gives the same state. The line says what the app knows.
RC11 · The event picker
  • It lists upcoming events only, soonest first, searchable by code or name. Replicating to a show that's over has no use.
  • Only the source's client. This is RC1 as written ("It lists the client's events"), and differs from Ops' recommendation. Copying across clients carries one client's page, Instagram and audiences onto another's show, which is the mistake page_other_client blocks at launch. Better to make it impossible than block it later. If Matas wants cross-client copies, it's a new ruling with its own frame.
  • The source's own event is listed only while it's upcoming. For a past show, "Duplicate" in the ⋯ menu already does the plain copy.
  • Empty: "No upcoming events for {client}." No search match: "No upcoming events match “{query}”."
RC12 · Words for errors and pickers
  • The dialog's five errors, the audience picker's three labels (kept as the app has them elsewhere), the learning-phase line, the run results and the sheet's errors are now rows. See the word list.
  • Nothing raw reaches the screen: not a server message, an HTTP code, an outcome code (refused, failed, noop) or a variable name. Each maps to a row, and anything unmapped shows the row for "nothing was added" or "the draft wasn't saved".
  • Results: after a run where some ad sets weren't added, the sheet stays open and lists them under "Not added to {n} ad sets:", each "{ad set}: refused, nothing changed on it" or "{ad set}: didn’t go through. Try again." Ad sets that already had it count as added and aren't listed.
  • Part way: when the run stops after some ad sets were written, it says how many: "Stopped part way: added to {n} ad sets, then stopped. Try again for the rest." The run's ledger means a retry skips what's done.
RC13 · RC-B, as built
  • Audiences row. The build is right. The account is written as everywhere else (RC2): Meta's name, then the venue in brackets. "9 found in NX Promoter (NX Newcastle) · 3 will be created". The row's words don't change; {account} fills as the Account row does.
  • Copy row. It stays out until copy is rewritten (R8). Until then the copy is the source's, so the kept line names it: "Objective, 18 ad sets, budgets, placements, interests, ad copy." Matas sees that the old copy came with it, and the launch checks still look for the other show's artist in it.
  • Frame RC-B2 replaces RC-B.
RC14 · How a campaign finds its stage
  • First, the name. Only stage words count, as whole words after the [CODE]:
    • SIGNUP, SIGN UP, SIGNUPS or REGISTRATION → Signup;
    • PRESALE or PRE SALE → Presale;
    • ON SALE, ONSALE, GEN SALE or GENERAL SALE → On sale;
    • SHOW WEEK or FINAL PUSH → Show week.
    PURCHASE, TRAFFIC, REACH, TICKET(S) and REG aren't stage words and no longer sort a campaign.
  • Then the objective, only where it means one stage: the draft's registration, a Complete Registration ad set or Meta's leads → Signup; the draft's purchase, an on-sale ad set or Meta's sales → On sale.
  • Traffic, awareness, engagement and reach run in every stage, so they decide nothing.
  • Anything still unknown goes under "Unsorted", last, after Show week, and only when it has campaigns. It carries no "Add … to…" actions, and one muted line: "The name and objective don’t say the stage, so these take no stage additions." Filing a guess under On sale is how a copy picks up the wrong stage.
  • Frame RC-F2 replaces RC-F: #1359's frame had the TRAFFIC and REACH campaigns under On sale, which this rule moves.
RC15 · Where the tree sits
  • Inside Linked campaigns on the event, for now.
  • Follow-up: it moves to its own section on the event page once #1160 (event-detail.tsx, open since 10 Nov) is merged or closed. Matas decides #1160.
Ops · The switch for adding creatives
  • Recorded as Ops ruled it: "Add creatives to…" from the tree sits behind a new OFFPIXEL_META_TREE_ADD_WRITES_ENABLED. It must be exactly "true", and it's off by default. The existing bulk-attach page is unchanged.
  • While it's off, the sheet still opens and ticks as usual, the button is off, and the line above it reads "Adding creatives from here is switched off."
  • "Add audience to…" works the same way behind its existing switch: "Adding audiences from here is switched off." No variable name is shown to Matas (RC12).

Acceptance

  • One forms: a stage with one campaign and one ad set reads "Add to 1 ad set in 1 campaign"; an addition to one ad set reads "to 1 ad set".
  • No draft: a campaign built in Ads Manager and linked to the event shows under its stage, muted with the line, and can't be ticked in either sheet.
  • Picker: only the source client's upcoming events. A past source event isn't listed. Search matches code or name.
  • Stages: [NX27-GLITTERBOX] TRAFFIC with a traffic objective lands under Unsorted, not On sale. [CODE] SIGNUP lands under Signup whatever its objective.
  • Switch off: with OFFPIXEL_META_TREE_ADD_WRITES_ENABLED unset, or set to anything but "true", the creatives sheet's button is off with the line, and no request leaves for Meta (CC-4's test).
  • Words: every string on these surfaces is a row, exactly. No server message, code or variable name shows.

Invented here

  • The no-draft line, the Unsorted line, and every error and result line.
  • "Nothing ticked".
  • The [NX27-GLITTERBOX] ON SALE · RETARGET campaign in RC-F2, and the audience and ad set names in RC-G.
  • Dates and counts in the frames.
