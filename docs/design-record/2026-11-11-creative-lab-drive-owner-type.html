Rulings

#Ruling
D1 Owner, then typeThis replaces S18's stage children. Under every stage folder that receives creatives, the next layer is the owner, one folder each, and under each owner is Videos and Statics.
  • An artist's folder is named exactly as the Lab lineup names them, the same string as 02 Source / Artist clips / {artist}. It's compared exact: never trimmed, case-folded or normalised (S22).
  • The promoter's folder is the client's name as written on the record (S13), for example Puzzle.
  • If an artist and the client share a name exactly, the promoter's folder is {Client} (promoter).
  • Example: 03 Creatives / 3 On sale / w/c 9 Nov / Luke Dean / Statics / P26-BDAY_luke-dean_artist-card-1_on-sale_9x16_v3.png.
D2 Who owns a renderA render's owner is its footage's owner (W1, migration 226), decided once at filing.
  • An artist: a render on that artist's clip (T1 on a clip, a UGC caption, quote mode, a triple-fit), or an artist card. A triple-fit's owner is its one clip's owner.
  • The promoter: a render on promoter footage, even when it features an artist (W8), plus T2 on the panel, T2 experience-led on a photo or clip, poster panels, and ticket-warning statics with no footage.
  • Two artists (b2b): no "Lineup" folder. A render has exactly one owner.
    • A b2b act that is one lineup entry (for example "Locky b2b CW") is one owner, under that entry's exact name.
    • An artist's clip featuring another lineup artist belongs to the clip's artist, the first-named. It's filed once, in that folder.
    • A shortcut in the other artist's folder wouldn't help: whoever opens that folder's link can't open a file kept elsewhere. If the second team needs it, Matas shares that one file.
  • An owner corrected after filing (W1 allows one correction): files already filed stay where they are, and only later filings follow the correction.
D3 Type
  • Videos holds renders with creative_lab_renders.kind = 'video'. Statics holds kind = 'static'.
  • A ticket warning or other approved piece that isn't a Lab render goes by its file: a video file to Videos, an image to Statics.
  • There are no other type folders. UGC, Ticket warnings and Content are retired from new cycles. CYCLE_CHILDREN becomes empty, and a new w/c {d Mon} folder is made with nothing in it.
  • Formats stay side by side in one type folder, told apart by the file name's _9x16 / _4x5 / _1x1 (S14). There are no format folders.
D4 Which stagesEvery place an approved creative is filed takes {owner} / {Videos | Statics}:
  • 1 Signup / Teaser / {owner} / {type}. This replaces Teaser / Artist · Promoter · Experience: an artist-voiced render goes under its artist, and experience-led work goes under the promoter, since it's promoter-owned (O76). The routing moves from voice to owner. A promoter render in the artist-first-person angle can't exist (W3).
  • 1 Signup / Announcement / {owner} / {type}. Nothing routes there today. This is its shape for when something does, or for a file Matas places by hand.
  • 2 Presale / Presale live / {owner} / {type}, and 2 Presale / Reminders / {owner} / {type}. A presale-live ticket warning goes to Presale live / Puzzle / Statics.
  • 3 On sale / w/c {d Mon} / {owner} / {type}. Every on-sale render and the cycle's ticket warnings go here.
  • 4 Show week / {owner} / {type}. It's still one folder for the week, with the owner layer under it.
  • Unchanged:
    • _Winners stays flat, shortcuts only, winners marked by name (S21).
    • 04 D2C stays flat. Its email headers and WhatsApp art are the promoter's comms, not approvals for an artist team.
    • 02 Source, 00, 01, 05 and 06.
D5 Made when first needed
  • An owner folder, and a type folder inside it, are made only when the first file for them is filed, never empty ahead of time. A new event's tree stops at Teaser, Announcement, Presale live, Reminders and 4 Show week, with no voice children.
  • Map keys are stable, never names (S19, S27): {stage key}/owner/artist:{artist_id} or {stage key}/owner/promoter, then /videos or /statics. For example: 03/3/wc/2026-11-09/owner/artist:{id}/statics.
  • Renames follow: an artist renamed in the Lab renames every owner folder of theirs, in every stage and cycle. A client renamed renames every promoter folder. File names never change (S19).
  • An artist taken off the lineup keeps their folders. Nothing is deleted.
D6 Existing folders
  • P26-BDAY, w/c 9 Nov:
    • Content / Luke Dean is moved, as the folder itself, so its id and any link Matas has shared still work. It becomes w/c 9 Nov / Luke Dean.
    • A Statics folder is made inside it, and its 6 files are moved into Statics.
    • The same goes for Content / Enzo Siragusa (3 files). A video file among them would go to Videos instead.
    • Both moved folders are recorded in the map under their owner keys.
    • UGC, Ticket warnings, the now-empty Content, and Teaser / Artist · Promoter · Experience stay where they are. The export never deletes, and a content manager can't.
  • Other events: none has a tree today, so there is nothing to migrate. A folder linked later through S24 keeps its own layout as it is, and filing adds the owner layer inside it.
  • The tool: moves only, never a rename, delete or permission change. It runs as a dry run by default and prints each move as from → to; --apply moves. It can safely run twice: a file already in place is skipped.
D7 Sharing
  • Sharing stays manual. Matas shares an owner folder's link himself. There are no automatic permissions, and shareEventFolder (S25) is unchanged.
  • No "copy link" per owner folder on the event card in this record. The Drive panel already opens the stage folder, and the owner folder is one click inside. If Matas finds himself opening Drive just to copy links, that's a later record, with the use in front of it.
  • An artist team's link is per cycle: each fortnight's w/c has its own Luke Dean. That's intended, because each approval is for that cycle's work.
  • Sharing an owner folder outside Off / Pixel needs the drive's sharing settings that HS17 already flags.
D8 File namesS14 is unchanged. The owner and type are in the path, never added to the name.
