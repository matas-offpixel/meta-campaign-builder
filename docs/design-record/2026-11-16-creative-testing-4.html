Audio files: a lower quality bar, and no supplier step

From Matas, 16 Nov. This record re-rules CT2 of 2026-11-16-creative-testing.html, and the parts of CT3, CT10 and CT11 that depend on it.

  • MP3 at 128 kbps or more is now accepted.
  • The supplier step is gone.
  • Rights handling stays as TT5 in 2026-11-16-creative-testing-2.html.

Everything else in CT1–CT12, TT1 and TT4–TT6, and TF1–TF4 stands. That includes CT2's one source, 02 Source / Audio / {artist}, and its rule that the Lab has no field for a link and never downloads audio itself. CT-A is redrawn here as AU-A. The example files are invented.

Rulings

#Ruling
AU1 · The quality bar (re-rules CT2's accepted files)
  • Accepted: WAV, AIFF, FLAC, or MP3 at 128 kbps or more. The file must be at least 30 seconds long, as before.
  • "Can't use this file: {reason}" fires only for these three reasons, worded exactly:
    • "Can't use this file: MP3 under 128 kbps";
    • "Can't use this file: shorter than 30 seconds";
    • "Can't use this file: it can't be read", for anything the Lab can't open or doesn't recognise as audio.
  • CT1's output is unchanged: AAC at 256 kbps, −14 LUFS, −1 dBTP. A 128 kbps source isn't raised in quality by this. Encoding at 256 just avoids losing more in the second encode.
AU2 · No supplier (withdraws CT2's supplier step)
  • A file in 02 Source / Audio / {artist} is ready as soon as its format passes AU1. There's no supplier field, no hold and no supplier line anywhere.
  • The rights note is replaced by a file line under each track with a file and on each snippet's render row: "{file name} · {format}". An MP3 adds its bitrate.
    • For example, "track two (club mix).aiff · AIFF".
    • For example, "LD - Track Three.mp3 · MP3 128 kbps".
    The line names the file a snippet was cut from, so a muted ad can be traced back to it.
  • CT3's pick rule becomes: only rows with a matched file that passes AU1 can be picked.
  • CT10: render rows carry the file line in place of the rights note.
  • CT11: the share link has no supplier step to leave out. It's otherwise unchanged.
AU3 · Rights stay with TT5
  • A Meta mute or rights rejection pauses that variant, takes it out of the test and flags its file. The line reads "Meta muted the audio (rights)".
  • A flagged file can't be picked until Matas clears the flag. That's unchanged from TT5.
  • In the picker, a flagged file's row shows the file line followed by " · Meta muted the audio (rights)", with its tick off.
AU4 · The Lab's strings

Gone:

  • "Who supplied this file?", its choices "{client}" and "{artist}'s team", and the "Who supplied it?" action;
  • "Name who supplied this file before it can run.";
  • the rights note, "Audio supplied by {supplier} · {file name} · {who}, {date}", on track rows and render rows.

Changed:

  • "Can't use this file: {reason}" now has only AU1's three reasons;
  • CT3's "matched, supplied file" is now "matched file that passes AU1";
  • CT-A's acceptance line "a confirmed match, a named supplier and a placed drop marker" is now "a confirmed match, a file that passes AU1 and a placed drop marker".

New:

  • the file line "{file name} · {format}", with the bitrate on an MP3;
  • the three reason strings;
  • the muted suffix on a flagged row.

Unchanged: "{n} of 5 picked", "Looks like {file name}", "Match", "No file in Drive yet", "{file name} · not in Spotify's top tracks", the Spotify no-answer line, the drop marker strings and the preview strings.

Frames

In AU-A, track 3's 128 kbps MP3 passes and is picked. Track 4's file is an MP3 under 128 kbps. Track 6 was muted by Meta in an earlier test, so its file stays flagged until Matas clears it.

Acceptance

  • The format check accepts WAV, AIFF, FLAC and MP3 at 128 kbps or more, at least 30 seconds long. A test covers each of the three reasons.
  • No supplier field, hold or line exists anywhere in the Lab, on render rows or in storage reads for the picker.
  • Track rows and render rows show the file line.
  • A snippet renders with a confirmed match, a file that passes AU1 and a placed drop marker.
  • A flagged file shows the muted suffix and can't be ticked.
  • Frame AU-A at 1280 and 393, from fixtures.

Invented here

  • The three reason strings' wording, the file line "{file name} · {format}" with the bitrate on an MP3, and the muted suffix on a flagged row.
